# Persona Director AI 运行时测试大纲

## 目标

在一次性调试存档中验证 AutoGen、AutoEvolve 和历史记录的真实闭环：游戏事件触发、请求入队、AI 实际调用、请求引用的上下文、结果应用方式和历史记录。测试不得修改源码、Git 或正式存档。

## 安全与工具边界

- 只允许使用 GABS MCP 的 `games_*` 结构化工具以及其镜像的 RimBridge 工具。
- 禁止 Computer Use、`codex-computer-use.exe`、内联 PowerShell、手写 TCP/GABP 客户端、读取或解析 bridge token。
- GABS 无法连接时立即报告 BLOCKED，不得 force takeover、重启游戏或自行绕过桥接。
- AI 服务为免费测试服务，允许真实调用；每个场景最多等待一个明确超时，禁止无限重试。
- CE/调试工具只能准备前置条件；被测的身份/关系变化必须由正常游戏机制完成。
- 使用一次性调试殖民地，不覆盖或保存为正式存档。

## 阶段 0：版本与环境基线

1. 确认 RimWorld 已重新启动并加载本轮新 DLL；若游戏进程早于 DLL 构建时间，停止并报告需要重启。
2. 确认当前地图、暂停状态、玩家派系、实验功能和免费 AI 服务可用。
3. 记录设置基线：AutoGen 总开关、六类开关/同步/preset/高级 preset、AutoEvolve 总开关/默认开关/模式/事件、目标 Pawn 独立配置。
4. 记录目标 Pawn 的 Persona、历史条数、身份、派系及关键上下文属性。
5. 确认日志中不再出现开局大量临时 Pawn Persona 分配或 `Could not find player faction.`；最终地图 Pawn 数与初始分配对象应一致。

## 阶段 1：AutoGen 新 Pawn 真实闭环

1. 临时启用实验功能、AutoGen 总开关和 Colonist 分类；内置 preset 使用 Story-Driven/preset1，高级 preset 先设为无。
2. 通过正常游戏事件生成并加入一个新 Pawn，优先使用“流浪者加入”等事件；不要直接编辑最终派系或身份。
3. 验证顺序：Pawn 真正上图 → 规则/随机库初始 Persona → baseline → AutoGen 入队 → AI 请求开始 → 返回 → 应用。
4. 验证临时候选/世界 Pawn 没有 Persona 分配日志。
5. 验证历史：初始规则分配不产生历史；AI AutoGen 应用后新增一条记录，记录原因与前后 Persona 正确。
6. 记录调用耗时、成功/失败、返回摘要和最终 Persona；不得输出私有 prompt 全文。

## 阶段 2：AutoGen 实际上下文

1. 在 RimTalk API History/请求历史中检查实际出站请求；只报告段落标题、布尔存在性、长度或脱敏摘要。
2. 同步模式：分类 `syncWithModSettings=true`，核对请求只引用总设置 Context 所启用的段落。
3. 自定义模式：选择另一安全的新 Pawn/分类，`syncWithModSettings=false`，配置一组明显不同的上下文开关，核对请求随之改变。
4. 在 AutoGen note 中加入唯一探针标记和一个能命中的 Scriban 条件，确认请求包含渲染结果而非原始模板。
5. 分别验证派系、种族模板：选择一个 Def 后，实际文本必须包含所选 DefName 和完整 `{{- ... -}}`，不得残留 `{0}` 或单花括号。
6. 核对请求采用所选内置 preset1；选择高级 preset 后再做一次调用，核对请求通过所选高级通道，Context 数据构建不应改变。

## 阶段 3：AutoEvolve 实际调用与应用模式

1. 选择一个地图 Pawn，启用 AutoEvolve 总开关和该 Pawn 独立开关；默认开关保持测试前基线。
2. 先用安全的手动触发验证请求链，确认 AI 实际调用、结果应用与历史新增。
3. Append 模式：记录旧 Persona，调用后必须保留旧内容并追加生成内容。
4. Overwrite 模式：再次调用，结果应由新内容替换，旧 Persona 不应继续作为最终正文前缀。
5. 比较两次请求的 Context 数据段和高级 preset；除触发说明/旧 Persona 外，数据构建应一致。
6. 每次调用后检查历史前后 Persona、原因、时间和数量。

## 阶段 4：合法身份变化触发

1. 准备一个地图上的非玩家 Pawn；允许用 CE/调试工具使其倒地，但不得直接把它改成囚犯。
2. 先将其 Persona 改为非初始 baseline，并启用该 Pawn 的 AutoEvolve；否则身份变化会按设计优先路由 AutoGen。
3. 由玩家正常下达抓捕命令并完成押送，使 Pawn 合法成为囚犯。
4. 验证触发一次且仅一次；上下文必须包含旧/新身份、旧/新派系名称、DefName 和与玩家派系的关系。
5. 验证请求进入 AutoEvolve 而不是 AutoGen，结果正常应用并写入一条历史。
6. 若桥接无法完成合法抓捕，标记 BLOCKED，不得用 CE 直接修改身份冒充通过。

## 阶段 5：事件触发与去重

1. 选择一种能安全合法制造的事件进行实际测试，优先新增特质；CE 可准备前置条件，但最终事件须由游戏系统发布。
2. 验证事件只触发一个 AI 请求，Context 包含事件名称与必要参与者信息。
3. 若测试出生，必须验证多胞胎去重并排除世界 Pawn 出生；无法稳定制造则保留为未测边界。
4. 婚姻、分手、直系亲属死亡分别记录是否实际覆盖，未覆盖不得写 PASS。

## 阶段 6：恢复与报告

1. 恢复所有临时开关、分类、preset、模式、note、Pawn 独立设置和游戏速度。
2. 核对设置语义与阶段 0 基线一致；不要求恢复一次性测试 Pawn 或其测试历史。
3. 每阶段向主会话发送：步骤、触发证据、实际上下文摘要、AI 调用证据、应用结果、历史变化、PASS/FAIL/BLOCKED、日志/截图路径。
4. 最终报告区分：已实测、仅静态确认、工具阻塞、需要人工复测。

## 终止条件

- Defender 再次告警、GABS 请求异常要求绕过、游戏崩溃、AI 连续两次相同失败、设置无法恢复或操作可能影响正式存档时，立即停止并报告。
